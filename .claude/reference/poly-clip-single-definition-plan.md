## Context

`.poly_clip()` (keep the rows of an n x 2 matrix that lie inside an `sp::SpatialPolygons` hull) is
defined twice: in `R/hull_utils.R:75` and in `R/boundary.R:73`. CLAUDE.md §6 and the implementation
summary (§5, `R/hull_utils.R`) record the `boundary.R` copy as technical debt. The goal is one
definition, in `R/hull_utils.R`, with no change in any result.

**Which copy runs today (checked 2026-11-05).** DESCRIPTION has no `Collate` field, so R sources
`R/` alphabetically: `boundary.R` first, then `hull_utils.R`, whose definition overwrites the first.
After `pkgload::load_all()`, `getSrcFilename(boundarylogic:::.poly_clip)` gives `hull_utils.R`, line
75. The `boundary.R` copy is dead code. All three callers already run the `hull_utils.R` copy:
`R/boundary.R:258` and `:292` (`bl_find_boundary()`, clipping contours to the global hull) and
`R/local_cf.R:804` (`bl_find_local_cf()`, the hull on each rotated plane).

## Implications

1. **Results: none.** The live function object is the `hull_utils.R` copy before and after, so no
   search, plot or print can change. The CLAUDE.md §4 "outputs proven equivalent" rule is met by
   construction, and is checked below.
2. **The hidden load-order dependence goes.** Today the result depends on alphabetical collation: a
   file rename or a `Collate` field that put `boundary.R` after `hull_utils.R` would make the dead
   copy take over without notice.
3. **The two copies differ only on inputs no caller passes.** The removed copy tests
   `length(Mxy) == 0L`, the kept copy `nrow(Mxy) == 0L`; on a bare (non-matrix) vector the kept copy
   stops with an error. Every caller passes `cbind(x, y)`, a matrix, so this is unreachable. The
   kept copy is not changed (minimal change, CLAUDE.md §5).
4. **Help file:** `devtools::document()` regenerates `man/dot-poly_clip.Rd` with one usage line
   instead of two and one description (today it merges both roxygen blocks). **NAMESPACE does not
   change:** the `sp::point.in.polygon` import comes from `.build_hull_polygon()`'s roxygen block in
   `hull_utils.R`, and `boundary.R`'s closed-contour check still uses it.
5. **pkgdown site:** `docs/reference/dot-poly_clip.html` and `docs/search.json` keep the duplicated
   usage until the next full `pkgdown::build_site()` (user's choice, 2026-11-05).
6. **A walkthrough fix:** `development/reference/review_section7_to_8.md:87` says `.poly_clip()` is
   "defined in `R/boundary.R`". That is already wrong for the copy that runs.
7. **Not affected:** the methodology-changes note (no method or numerical change; its code-improvements

|---|---|---|
