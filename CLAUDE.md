# CLAUDE.md — boundarylogic

## 1. Project Identity

`boundarylogic` is an R package that operationalises a PhD methodology for post-hoc interpretability of binary classification models. It projects high-dimensional data into a 2D biplot (PCA or CVA), approximates the model's decision boundary in that space, and finds counterfactuals — the minimum change to an observation that flips the prediction.

**Three-phase workflow:**
- Phase 1: data prep → model → biplot projection → prediction grid → `bl_result` (the central anchor object)
- Phase 2 (global): nearest boundary point per observation, surrogate model, robustness
- Phase 3 (local): single-observation biplot rotation → counterfactual → Shapley attribution → sparse counterfactual

The `bl_result` object is what everything downstream consumes.

## 4. Critical Constraints — Never Do

- **Never simplify the maths to make code shorter.** Replace mathematical logic only when outputs are proven equivalent.
- **Never alter default scaling, centring, or projection conventions** without explicit instruction.
- **Never apply the global biplot's Z-space hull polygon (from `bl_grid`) inside `bl_find_local_cf()`.** The SVD rotation invalidates its coordinates. The local search instead rebuilds a hull on each rotated plane from the training data and the target (`hull = TRUE`, the default since 2026-11-05; the thesis's plausibility rule, p.117), then applies `set_filters` and `train_ranges`. See `documentation/local-convex-hull.md`.
- **Never entangle plotting code with computation code.** `plot_biplotEZ()` renders; it does not compute boundary points or projections.
- **Never remove metadata fields** from S3 objects (`V`, `tV`, `X_center`, `X_sd`, `train_ranges`, etc.). These are required for inverse projection and downstream analysis.
- **Never change the `cutoff` default from 0.5.** Other values are accepted but are methodologically invalid under the current method.
- **Never change the XGB model format.** When calling `bl_wrap_model(model_type = "XGB")`, the `model` argument must be `list(model = <xgb.Booster>, features = <character vector>)`. XGB is no longer supported by `bl_fit_model()`.
- **Never expose `outlie`, `calc_hull`, or `bl_robustness()` as sequential steps in examples or vignettes.** These are internal or redundant.
- **Never add a `boundary =` parameter back to `plot_biplotEZ()`.** Counterfactual arrows belong exclusively in `bl_pick_point(bl_result, bl_boundary = bl_bnd)` — drawing n arrows at plot-flush time caused unsuppressable zero-length arrow warnings.
- **Never add `rotate_deg` back to `plot.bl_local_result()` / `plot.bl_sparse_result()`.** It is for viewing the global biplot only (`plot_biplotEZ()`, `plot.bl_surrogate()`); the local biplot's orientation comes from `.bl_rotate()` and is never turned further. Passing it to a local plot stops with an error.
- **Never use literal non-ASCII characters in R source files.** Use ASCII equivalents (`--` for em dash, `x` for ×, `>=` for ≥) or `\uXXXX` escape sequences in code strings. The Edit tool cannot reliably write `\uXXXX` escapes — use a Python one-liner via Bash for bulk replacement.

Wired into `plot_biplotEZ()`, `plot.bl_projection()`, `plot.bl_local_result()`, `plot.bl_surrogate()`, and (via pass-through) `plot.bl_sparse_result()`. The scaling is **display-only** — it never alters the projection, grid, or what the model/`predict_fn` sees. Distinct from `X_center`/`X_sd` (internal PCA standardisation) and the `standardise` flag.
- **Raw-unit feature *values* (display-only).** Any plot/print that shows feature values (observed, counterfactual, sparse CF, target) must convert them to original units via `.scale_to_raw(values, bl_result$scaling, var_names, kind)` (`R/data_prepare.R`) when `scaling` is present. **The `kind` argument is the correctness rule:** a *level* (an observed/CF/sparse value) maps `value*scale + center` (`kind = "level"`); a *delta* (a difference such as the Shapley `data_to_boundary` change) maps `value*scale` with **no** centre term (`kind = "delta"`). No-op when `scaling` is `NULL`; warns and leaves values unchanged if it doesn't cover every feature. The helper strips names — re-attach `names()` after calling it if the display needs them. Stored objects stay in model units (convert only at display). Do **not** convert quantities that are not in feature units — e.g. Shapley *contributions* (`shapley_cause`) are prediction-impact units and must be left as-is. Currently applied in `plot.bl_shapley()`, `print.bl_shapley()`, `print.bl_sparse_result()`, `print.bl_target()`, `print.bl_counterfactual()`, and `print.bl_local_result()`. The three observed-vs-counterfactual tables (`print.bl_local_result()`, `print.bl_shapley()`, `print.bl_sparse_result()`) share one builder, `.cf_compare_table()`; change it there so they stay in the same layout. They, the Target/Counterfactual blocks and the sparse path print in fixed notation with 2 decimals, widened per feature row (up to 4) where a change would print as 0.00 (`.fmt_digits()`, `.fmt_fixed()`, `.format_cf_table()`); the stored table stays unrounded. The Shapley plot labels read `"variable: observed -> counterfactual"` with and without a scaling, with the same per-row decimals (`.shapley_labels()`, `R/shapley.R`), and the bar values use `.fmt_fixed(s, .fmt_digits(s))`. These rules are written up once, in `documentation/scaling_axis_relabel_note.md` ("Display conventions"); point there rather than restating them.

The harness's Step 16 converts its applicant this way.
- **Counterfactual objects mirror `bl_target`.** `bl_find_local_cf()` returns `bl_local$bl_counterfactual` (class `"bl_counterfactual"`, via `.make_bl_counterfactual()`) parallel to `bl_local$bl_target`: it stores the boundary point's values in **model units** (`x_cf = B_x`) plus `scaling`, and its `print` method converts to raw at display time. When adding a new "point" companion object, follow this pattern (store model-unit values + `scaling`; convert in `print` via `.scale_to_raw`).
- **In scripts/vignettes, fit standardisation on the training split only.** When demonstrating `bl_set_scaling()`, split first (`bl_prepare_data()` on raw data — the hull filter self-standardises, so filtering on raw vs standardised is equivalent), compute `center`/`scale` from `bl_dat$train_data`, apply those stats to both `train_data` and `test_data`, then record with `bl_set_scaling()`. Computing the scaling on the full dataset leaks test information. See `development/03_loan_status_Boundary_Logic.R` v2 block.
- **Distance-measure functions** use the `distance = c("auto", "mahalanobis", "euclidean")` parameter convention with `"auto"` as the default, resolved by `.resolve_distance()` (`R/utils.R`) to the thesis rule (§3.9.1): `"euclidean"` under PCA, `"mahalanobis"` under CVA and for a `bl_result` without `method` (since 2026-11-05; applies to `bl_find_local_cf()`, `plot.bl_boundary()`, `bl_robustness()`). The Mahalanobis path reads `bl_result$metric_inv` (full `W^{-1}`) or `bl_result$metric` (raw `W`, e.g. `sqrt(diag(W))` for per-feature standardisation); the Euclidean path divides by the total SD `X_sd` (in the local search, the X-space distance `.cf_sq_distance()`, as `bl_find_boundary()`'s `dist_x`). ## 6. Key Architectural Facts

- **Two data entry paths are distinct:** `bl_prepare_data()` is for the in-package model-building workflow — it handles the train/test split and runs `bl_filter_outliers()` internally (via the `hull_fraction` parameter), returning `"bl_filter_result"`. `bl_wrap_data()` is for users with an already-prepared dataset and externally trained model who want boundary logic purely for visualisation and explanation — it does not filter, returning `"bl_data"`. Both classes are accepted by `bl_assemble()` and `bl_build_result()`.
- **`bl_prepare_data()`'s `hull_fraction` default is `1` (no outlier removal; since 2026-11-05, was `0.9`),** as the thesis makes outlier removal optional. Each application sets its own value: the loan harness, vignette and README loan example pass `0.9` (the thesis's loan example), the Pima example passes `1`. `bl_filter_outliers()` keeps `0.9`. The iris test fixtures use the default.
- **`bl_prepare_data()`'s split depends only on the rows and the seed** (`set.seed(seed); sample(n, ...)`), so re-running it on the same rows with fewer `feature_cols` gives the same train/test rows: refit a pruned model this way (the Pima `02b_prune-refit.R` checks it).
- `b_margin` controls the decision boundary contour band half-width directly (default `0.001`, valid range `(0, 0.5)`). It is stored on `bl_grid$b_margin` and propagates to `bl_result$b_margin`. Predictions are independently stored at 3 d.p. via `floor(x * 1000) / 1000` in `.pred_function()`. These are separate concerns.
- The hull polygon in `bl_result` always comes from `bl_grid` (final Z-space), never from `bl_filter_result` (a lightweight 2-PC space of the standardised features).
- **`bl_pick_point(bl_boundary = bl_bnd)` must search the rows the boundary was found on:** `bl_find_boundary()` defaults to `test_data` but `bl_pick_point()` defaults to `train_data`, so pass `data = bl_results$test_data` to both.
- CVA forces `standardise = FALSE` internally inside `bl_build_projection()`, regardless of the user-supplied value.
- In `bl_find_boundary()`, `train_ranges` are applied post-selection (after the nearest boundary point is identified), not as a pre-filter on contour segments.
- In `bl_find_local_cf()`, the hull on the rotated plane (`hull = TRUE`, 2D, `.poly_clip()`) runs first, then `set_filters` (actionability) before `train_ranges` (feasibility), within each candidate component-pair loop. `hull = FALSE` reproduces the search before 2026-11-05 exactly; the rotation scripts `17_1`-`17_3` pin it. On the Pima example the hull moves 11 of 79 test targets and the TP target (whose constrained runs that hold *Age* then have no counterfactual); the loan harness is unchanged. Actionability constraints are typically more selective, so running them first enables per-segment early exit (`if (!any(keep)) next`). Filter 4 (model re-score) is not batched -- it stays per-segment to avoid O(n) vertex accumulation across pairs.
- `bl_build_result()` always returns a `bl_result` object (class `c("bl_result", "list")`), even when `bl_model = NULL`. In that case the model and grid fields are NULL but the object is still a `bl_result`, not a `bl_projection`.
- `.poly_clip()` exists in both `hull_utils.R` and `boundary.R`. The authoritative copy is in `hull_utils.R`. Do not add a third copy.
- `bl_build_projection()` computes and stores the within-class metric matrix `W` (`metric`), its inverse via Cholesky (`metric_inv`), and the `metric_type` tag. These propagate through `bl_assemble()` into `bl_result`. The metric is the same `W` used by CVA's eigenproblem -- distances measured with it are consistent with the biplot axes. See `2 implementation_summary.txt` Section 4.2.1.
- **`"fixed"` is a tolerance in the search, then a restore.** `bl_find_local_cf()` accepts a fixed feature within `.fixed_tol` = 0.5 model units (a 2D boundary vertex rarely holds it exactly), then `.restore_fixed()` sets each moved fixed feature back to observed and keeps that point when it still crosses the boundary and is within `train_ranges`. `B_x`/`B_z`/`B_pred` are then the restored point; `dist_*` and the per-pair tables stay the search's; `fixed_check` records the outcome. **The restore is strict (2026-11-04):** when the restored point fails, `solution_found` is `FALSE`, `fixed_check` is kept with `applied = FALSE`, and `blocking_constraint` says why and that changing the other features' constraints may make a counterfactual possible. A reported counterfactual therefore always holds every fixed feature exactly.
- **`"integer"` is rounded after the search, then re-checked.** `set_filters()` takes `"integer"` alone, with a direction (`c("increase", "integer")`, either order) or with a range (`list(c(min, max), "integer")`); every reader parses constraints with `.parse_constraint()`, never `v == "fixed"` on a vector. After the fixed restore, `.round_integers()` tries the whole values (raw units) just below and above for every moved integer feature, keeps the combinations that still cross and meet every constraint and `train_ranges`, and takes the nearest in X-space by the search's selector (`.cf_sq_distance()`: Mahalanobis, or total-SD Euclidean; so with Mahalanobis it can pick a whole value further from observed: in the harness `credit_score` 634.22 becomes 635, not 634). None valid: no solution. `integer_check` records the outcome. See `documentation/fixed-constraint-restore.md` §5.
- **The CVA group factor's level order is part of the result.** `bl_build_projection()` keeps the TP/TN/FP/FN levels alphabetical (`FN, FP, TN, TP`, as `as.factor()` gives). Reordering them perturbs `V` numerically, which is enough to move `.bl_rotate()`'s under-determined plane and change every Phase 3 number (measured 2026-10-30). Empty groups are dropped, with a message.
- **The sparse CF is greedy, and a zero Shapley value is "No effect".** `bl_shapley()` labels `abs(shapley) < 1e-8` "No effect" (the PhD rule counted 0 as "Supports"); `bl_find_sparse_cf()` changes "Supports" features one at a time, largest |Shapley| first, re-scoring the model, and stops once the boundary is crossed (`sparse_path` records it). See `documentation/sparse-counterfactual.md`.
- `bl_find_local_cf()` selects the best eigenvector pair by the thesis rule (`distance = "auto"`, since 2026-11-05): squared Mahalanobis distance in X-space under CVA, and under PCA the Euclidean distance in X-space with each feature divided by its total SD (`dist_x`, `all_distances_x`), which under a standardised PCA equals the 2D Z-distance at the search point (orthonormal rotated loadings) but also measures off-plane points (the `"integer"` candidates) correctly. An explicit `"euclidean"` under CVA is that X-space metric, not the plane distance. Within-pair selection (nearest valid contour vertex) is 2D Euclidean. **Under CVA the Mahalanobis selector ranks the pairs as the plane distance does, by construction:** biplotEZ builds `M = W^{-1/2} V`, so `V'WV = I/(n-g)`; the per-pair rotation `A` cancels (`A A' = I`), so `d2_M = (n-g) * dist_z^2` for in-plane points, for every pair (15992 on the loan harness; also for 2-group CVA). The thesis selects by Euclidean under PCA and Mahalanobis under CVA (final thesis p.86, §3.9.1; p.106 in the 30 Sept 2025 draft) and says only qualitatively that plane distances correspond to Mahalanobis distances (final p.91); the (n-g) factor comes from the package's W/(n-g), since the thesis's W is the SSP (final p.48), which gives a factor of 1. The PhD code ran the pair search under CVA only. **Under PCA the Mahalanobis (`W_binary`) and Euclidean rules differ** (51 of 221 rows in `17_1`'s set-up); the PCA default was `W_binary` Mahalanobis until 2026-11-05 and is now the thesis's Euclidean rule (rotation note §4.4, resolved). The rotation scripts `17_1`-`17_3` pin `distance = "mahalanobis"`, the selector their measurements used. Paper 1 (CVA) is unchanged. See the rotation note §2.5, §3.4, §4.4.
- **The boundary searches are deterministic: `.nearest_idx_block()` takes the exact nearest vertex** (`max.col(-d2, ties.method = "first")`). R's default `"random"` -- inherited from the PhD code -- treated every vertex within 1e-5 of the *farthest* vertex's squared distance as tied and drew one from the session RNG. That was the cause of the repeat-call and call-history drift recorded in the rotation note §5.3 and §5.9 (fixed 2026-10-30), not the rotation, which is bit-identical across calls. Never use a `max.col()`/`which.max()` variant with random ties on distances. See `documentation/nearest-vertex-tie-break.md`.
- `plot.bl_boundary()` and `bl_robustness()` standardise each variable by the thesis rule by default (`distance = "auto"`, since 2026-11-05): under CVA by `sqrt(diag(W))` (within-class SD per feature, `"mahalanobis"`), which amplifies features that are good class separators; under PCA by `X_sd` (total SD, `"euclidean"`, the thesis's §4.2.2 rule). Either can be passed explicitly. A Mahalanobis check is printed (and returned as `mahalanobis_check`) when Mahalanobis is used: the plotted measure squared, `sum(vec_to_boundary_sd^2)`, against the full `v' W^-1 v`; see `2 implementation_summary.txt` Section 4.6.1 for why the full Shapley decomposition is theoretically better but not used in Phase 2.

## 7. Adding a New Model Type

Two distinct paths depending on where the type should be supported.

**`bl_wrap_model()` only** (externally fitted model, complex training, or non-parsnip engine):
1. Add the type string to `valid_types` in `bl_wrap_model()` (`R/model_fit.R`)
2. Add a prediction branch in `.pred_function()` (`R/predict_utils.R`)
3. Test with the iris two-class binary dataset

**`bl_fit_model()` + `bl_wrap_model()`** (simple parsnip-compatible type; current four are GLM, SVM, NNET, RForest):
1. Add the type string to `valid_types` in both `bl_fit_model()` and `bl_wrap_model()` (`R/model_fit.R`)
2. Add a fitting branch in `.fit_model()` (`R/model_utils.R`)
3. Add a prediction branch in `.pred_function()` (`R/predict_utils.R`)
4. Test with the iris two-class binary dataset
5. Add the new type to the supported model types table in the `bl_fit_model()` roxygen header
