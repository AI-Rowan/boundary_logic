# CLAUDE.md — boundarylogic

## 1. Project Identity

`boundarylogic` is an R package that operationalises a PhD methodology for post-hoc interpretability of binary classification models. It projects high-dimensional data into a 2D biplot (PCA or CVA), approximates the model's decision boundary in that space, and finds counterfactuals — the minimum change to an observation that flips the prediction.

**Three-phase workflow:**
- Phase 1: data prep → model → biplot projection → prediction grid → `bl_result` (the central anchor object)
- Phase 2 (global): nearest boundary point per observation, surrogate model, robustness
- Phase 3 (local): single-observation biplot rotation → counterfactual → Shapley attribution → sparse counterfactual

The `bl_result` object is what everything downstream consumes.

## 4. Critical Constraints — Never Do

- **Never simplify the maths to make code shorter.** Replace mathematical logic only when outputs are proven equivalent.
- **Never alter default scaling, centring, or projection conventions** without explicit instruction.
- **Never apply the global biplot's Z-space hull polygon (from `bl_grid`) inside `bl_find_local_cf()`.** The SVD rotation invalidates its coordinates. The local search rebuilds a hull on each rotated plane from the training data alone (the thesis's plausibility rule, p.117); the mechanics are in §6 and `documentation/local-convex-hull.md`.
- **Never change `.bl_rotate()` or implement its proposed replacement without an explicit instruction** (§9).
- **Never let `set_filters = NULL` switch off the hull or the training ranges.** `.filter_switches()` reads `NULL` (and a `bl_filters` object without the fields) as both on, so a search without a filter object stays the thesis's constrained search; only an explicit `set_filters(tgt, hull = FALSE, train_ranges = FALSE)` gives the unconstrained counterfactual. Reason: `documentation/local-convex-hull.md` §6.
- **Never entangle plotting code with computation code.** `plot_biplotEZ()` renders; it does not compute boundary points or projections.
- **Never remove metadata fields** from S3 objects (`V`, `tV`, `X_center`, `X_sd`, `train_ranges`, etc.). These are required for inverse projection and downstream analysis.
- **Never change the `cutoff` default from 0.5.** Other values are accepted but are methodologically invalid under the current method.
- **Never change the XGB model format.** When calling `bl_wrap_model(model_type = "XGB")`, the `model` argument must be `list(model = <xgb.Booster>, features = <character vector>)`. XGB is no longer supported by `bl_fit_model()`.
- **Never show in examples or vignettes what §8 lists** (`outlie`, `calc_hull`, `bl_robustness()` after `plot(bl_bnd)`, `bl_filter_outliers()` as a step).
- **Never add a `boundary =` parameter back to `plot_biplotEZ()`.** Counterfactual arrows belong exclusively in `bl_pick_point(bl_result, bl_boundary = bl_bnd)` — drawing n arrows at plot-flush time caused unsuppressable zero-length arrow warnings.
- **Never add `rotate_deg` back to `plot.bl_local_result()` / `plot.bl_sparse_result()`.** It is for viewing the global biplot only (`plot_biplotEZ()`, `plot.bl_surrogate()`); the local biplot's orientation comes from `.bl_rotate()` and is never turned further. Passing it to a local plot stops with an error.
- **Never use literal non-ASCII characters in R source files** (roxygen comments included; scan `R/*.R` for characters above 127 before finishing an R/ edit). Use ASCII equivalents (`--` for em dash, `x` for ×, `>=` for ≥) or `\uXXXX` escape sequences in code strings. The Edit tool cannot reliably write `\uXXXX` escapes — use a Python one-liner via Bash for bulk replacement.

- **After implementing any plan: stop after `devtools::document()` and `devtools::test()` pass.** Report the PASS/FAIL count and wait. Do NOT proceed to `git add`, `git commit`, or `git push` unless the user explicitly asks — even in auto-accept mode.
- Add `roxygen2` documentation (`#' @param`, `#' @return`, `#' @export`) to every exported function.
- **roxygen2 `@importFrom` directives must be single-line only.** Multi-line `@importFrom` (continuation lines starting with `#'   `) cause a hard roxygen2 parsing error. If you need to import many symbols from one package, split them across multiple `@importFrom` directives, e.g. `#' @importFrom ggplot2 aes ggplot geom_col` on one line, `#' @importFrom ggplot2 scale_fill_manual theme_bw` on the next. (Discovered 2026-06-08 when fixing the ggplot2 imports of `plot.bl_shapley()` and `plot.bl_boundary()`.)
- Validate inputs with the `stop_if_*()` helpers in `utils.R`, always with `call. = FALSE`.
- Name the assembled pipeline result `bl_results` in scripts (not `result` or `bl_result`).
- Name the Shapley object `bl_shapley_values` in scripts (not `bl_shap`, to avoid confusion with the Python SHAP library).
- Run `devtools::test()` after any change to a core function.
- Before modifying a core function: read its roxygen header, grep for callers, check what `bl_result` fields flow from it, then make a minimal change without refactoring surrounding code.
- Every new base-R plotting function (one that calls `graphics::*` directly) must open a graphics device if none is active: `if (grDevices::dev.cur() == 1L) grDevices::dev.new()` at the top of the function body, after input validation. Add `@importFrom grDevices dev.cur dev.new` to its roxygen block.
- **Helpers that draw on a temporary off-screen device must restore the caller's device:** save `prev_dev <- dev.cur()`, close only their own device (`dev.off(<own dev>)`), then `if (prev_dev > 1L) dev.set(prev_dev)` (pattern in `.build_hull_polygon()`). A bare `dev.off()` leaves R's *next* open device active.
- **Every biplot plot method must accept `new_title = NA`** for a custom title, applied as `if (!is.na(new_title)) <biplot_obj>$Title <- new_title` after the biplotEZ object is fetched (and after any auto-generated title is assigned, so the user override wins). biplotEZ renders `$Title` via `graphics::title()` at plot-flush time. Do not validate `new_title` (none of the plot methods do); `title()` coerces most inputs via `as.character()` -- only non-coercible types (a function/closure or environment) error, and they error from inside the biplotEZ `plot()` flush, not from arg handling. Implemented uniformly across `plot_biplotEZ()`, `plot.bl_result()` (via `...`), `plot.bl_local_result()`, `plot.bl_surrogate()`, and `plot.bl_sparse_result()` (via `...`). `plot.bl_projection()` has no `new_title` (adding it is listed in `documentation/future-improvements-review.md`).
- **Raw-unit biplot axes.** When `bl_result$scaling` is present (set via `bl_set_scaling()` when the user standardised features before model fitting), every biplot plot method must relabel its axes into original units by calling `.bl_rescale_biplot_axes(<biplot_obj>, bl_result$scaling, var_names)` **after** any rotation and `new_title` override, **before** the first `plot()`. The helper transforms only `$means`/`$sd` (and forces `$scaled`/`$center` TRUE); it never touches geometry (`$Z`, `$Lmat`, `$ax.one.unit`), so plotted positions are byte-identical. It is a no-op when `scaling` is `NULL` (back-compatible with older `bl_result` objects). Wired into `plot_biplotEZ()`, `plot.bl_projection()`, `plot.bl_local_result()`, `plot.bl_surrogate()`, and (via pass-through) `plot.bl_sparse_result()`. The scaling is **display-only** — it never alters the projection, grid, or what the model/`predict_fn` sees. Distinct from `X_center`/`X_sd` (internal PCA standardisation) and the `standardise` flag.
- **Raw-unit feature *values* (display-only).** Any plot/print that shows feature values (observed, counterfactual, sparse CF, target) must convert them to original units via `.scale_to_raw(values, bl_result$scaling, var_names, kind)` (`R/data_prepare.R`) when `scaling` is present. **The `kind` argument is the correctness rule:** a *level* (an observed/CF/sparse value) maps `value*scale + center` (`kind = "level"`); a *delta* (a difference such as the Shapley `data_to_boundary` change) maps `value*scale` with **no** centre term (`kind = "delta"`). No-op when `scaling` is `NULL`; warns and leaves values unchanged if it doesn't cover every feature. The helper strips names — re-attach `names()` after calling it if the display needs them. Stored objects stay in model units (convert only at display). Do **not** convert quantities that are not in feature units — e.g. Shapley *contributions* (`shapley_cause`) are prediction-impact units and must be left as-is. Currently applied in `plot.bl_shapley()`, `print.bl_shapley()`, `print.bl_sparse_result()`, `print.bl_target()`, `print.bl_counterfactual()`, `print.bl_local_result()`, and the fixed/integer notes `.fixed_text()` and `.integer_text()`. The three observed-vs-counterfactual tables share one builder, `.cf_compare_table()`; change it there so they stay in the same layout. The number formats (2 decimals widened per row, the Shapley `"observed -> counterfactual"` labels) are written up once, in `documentation/scaling_axis_relabel_note.md` ("Display conventions"); read it before changing a print or plot method.

## 6. Key Architectural Facts

- **Two data entry paths are distinct:** `bl_prepare_data()` is for the in-package model-building workflow — it handles the train/test split and runs `bl_filter_outliers()` internally (via the `hull_fraction` parameter), returning `"bl_filter_result"`. `bl_wrap_data()` is for users with an already-prepared dataset and externally trained model who want boundary logic purely for visualisation and explanation — it does not filter, returning `"bl_data"`. Both classes are accepted by `bl_assemble()` and `bl_build_result()`.
- **`bl_prepare_data()`'s `hull_fraction` default is `1` (no outlier removal; since 2026-11-05, was `0.9`),** as the thesis makes outlier removal optional. Each application sets its own value: the loan harness and vignette pass `0.9` (the thesis's loan example), as does the README's iris quick start; the README's Pima section and the Pima example pass `1`. `bl_filter_outliers()` keeps `0.9`. The iris test fixtures use the default.
- **`bl_prepare_data()`'s split depends only on the rows and the seed** (`set.seed(seed); sample(n, ...)`), so re-running it on the same rows with fewer `feature_cols` gives the same train/test rows: refit a pruned model this way (the Pima `02b_prune-refit.R` checks it).
- `b_margin` controls the decision boundary contour band half-width directly (default `0.001`, valid range `(0, 0.5)`). It is stored on `bl_grid$b_margin` and propagates to `bl_result$b_margin`. Predictions are independently stored at 3 d.p. via `floor(x * 1000) / 1000` in `.pred_function()`. These are separate concerns.
- The hull polygon in `bl_result` always comes from `bl_grid` (final Z-space), never from `bl_filter_result` (a lightweight 2-PC space of the standardised features).
- **`bl_pick_point(bl_boundary = bl_bnd)` must search the rows the boundary was found on:** `bl_find_boundary()` defaults to `test_data` but `bl_pick_point()` defaults to `train_data`, so pass `data = bl_results$test_data` to both. Its arrows use unrotated boundary coordinates, so draw the biplot with `rotate_deg = 0` when using it (otherwise they are misaligned); it skips a row whose boundary point is not finite.
- CVA forces `standardise = FALSE` internally inside `bl_build_projection()`, regardless of the user-supplied value.
- In `bl_find_boundary()`, `train_ranges` are applied post-selection (after the nearest boundary point is identified), not as a pre-filter on contour segments.
- **The empty-region rule uses the training data, in both searches** (since 2026-11-06): a contour still closed after the hull clip is kept only if it encloses training rows on that plane (`.encloses_data()`, `R/hull_utils.R`; thesis §3.10 step 4, p.93). In `bl_find_boundary()` the searched rows decided before, so results depended on `data`/`tdp`; in `bl_find_local_cf()` it applies only with the hull on. Each rotated plane's hull is the training data's alone (no target).
- **B1's `dist_x`/`dist_mahalanobis` are reported only; importance and robustness use B2's in-plane gap** `(Z_obs - B_z) %*% tVr` (thesis §4.2.2). B1's gap `B_x - x_obs` also resets the observation's off-plane part (59–80% of its squared length on the loan and Pima models), so switching B2 to it made the ranking measure the reconstruction error and was rejected (2026-11-06; `documentation/algorithms.md` F3). The Pima example uses the global √d²_M only to pick its targets.
- In `bl_find_local_cf()`, the hull on the rotated plane (plausibility, 2D, `.poly_clip()`, then the empty-region rule) runs first, then the actionability constraints before `train_ranges` (feasibility), within each candidate component-pair loop. **All three are set in `set_filters()`** (since 2026-11-06): the per-variable constraints and the switches `hull = TRUE` and `train_ranges = TRUE`; `bl_find_local_cf()` has no `hull` argument. With `train_ranges = FALSE` the search passes `train_ranges = NULL` to `.restore_fixed()` and `.round_integers()` too. `set_filters(tgt, hull = FALSE)` reproduces the search before 2026-11-05 exactly under CVA; under PCA it also needs `distance = "mahalanobis"` (the earlier PCA default). The rotation scripts `17_1`-`17_3` pin both. On the Pima example the hull moves 11 of 79 test targets and the TP target (whose constrained runs that hold *Age* then have no counterfactual); the 2026-11-06 refinements (training-only hull, empty-region rule) move 4 more test rows and no Paper 1 run, and on the loan harness they move the Step 11 and Step 16 counterfactuals. Actionability constraints are typically more selective, so running them first enables per-segment early exit (`if (!any(keep)) next`). The model re-score (the last filter) is not batched -- it stays per-segment to avoid O(n) vertex accumulation across pairs. A target inside every training range can lie outside a plane's hull; that is how the hull works (`documentation/local-convex-hull.md` §3).
- `bl_build_result()` always returns a `bl_result` object (class `c("bl_result", "list")`), even when `bl_model = NULL`. In that case the model and grid fields are NULL but the object is still a `bl_result`, not a `bl_projection`.
- **The local biplot colours its grid only inside the plane's hull**, as the global biplot does (`plot.bl_local_result(trim_to_hull = NULL)` follows `x$hull`; `.grid_in_hull()`); `bl_find_local_cf()` stores `hull_polygon` also with the hull off, so the plot never computes geometry.
- `.poly_clip()` is defined once, in `hull_utils.R` (the `boundary.R` copy, which the load order made dead code, was removed on 2026-11-05); `bl_find_boundary()` and `bl_find_local_cf()` both call it. Do not add a second copy.
- `bl_build_projection()` computes and stores the within-class metric matrix `W` (`metric`), its inverse via Cholesky (`metric_inv`), and the `metric_type` tag. These propagate through `bl_assemble()` into `bl_result`. The metric is the same `W` used by CVA's eigenproblem -- distances measured with it are consistent with the biplot axes. See `2 implementation_summary.txt` Section 4.2.1.
- **`"fixed"` is a tolerance in the search, then a restore.** `bl_find_local_cf()` accepts a fixed feature within `.fixed_tol` = 0.5 model units (a 2D boundary vertex rarely holds it exactly), then `.restore_fixed()` sets each moved fixed feature back to observed and keeps that point when it still crosses the boundary and is within `train_ranges`. `B_x`/`B_z`/`B_pred` are then the restored point; `dist_*` and the per-pair tables stay the search's; `fixed_check` records the outcome. **The restore is strict (2026-11-04):** when the restored point fails, `solution_found` is `FALSE`, `fixed_check` is kept with `applied = FALSE`, and `blocking_constraint` says why and that changing the other features' constraints may make a counterfactual possible. A reported counterfactual therefore always holds every fixed feature exactly.
- **`"integer"` is rounded after the search, then re-checked.** `set_filters()` takes `"integer"` alone, with a direction (`c("increase", "integer")`, either order) or with a range (`list(c(min, max), "integer")`); every reader parses constraints with `.parse_constraint()`, never `v == "fixed"` on a vector. After the fixed restore, `.round_integers()` tries the whole values (raw units) just below and above for every moved integer feature, keeps the combinations that still cross and meet every constraint and `train_ranges`, and takes the nearest in X-space by the search's selector (`.cf_sq_distance()`: Mahalanobis, or total-SD Euclidean; so with Mahalanobis it can pick a whole value further from observed: in the harness `credit_score` 634.05 becomes 635, not 634). None valid: no solution. `integer_check` records the outcome. See `documentation/fixed-constraint-restore.md` §5.
- **The CVA group factor's level order is part of the result.** `bl_build_projection()` keeps the TP/TN/FP/FN levels alphabetical (`FN, FP, TN, TP`, as `as.factor()` gives). Reordering them perturbs `V` numerically, which is enough to move `.bl_rotate()`'s under-determined plane and change every Phase 3 number (measured 2026-10-30). Empty groups are dropped, with a message.
- **The sparse CF is greedy, and a zero Shapley value is "No effect".** `bl_shapley()` labels `abs(shapley) < 1e-8` "No effect" (thesis Appendix A counted 0 as "Supports" for a class-0 target and "Contradicts" for a class-1 target); `bl_find_sparse_cf()` changes "Supports" features one at a time, largest |Shapley| first, re-scoring the model, and stops once the boundary is crossed (`sparse_path` records it). See `documentation/sparse-counterfactual.md`.
- `bl_find_local_cf()` selects the best component pair by the thesis rule (`distance = "auto"`): squared Mahalanobis distance in X-space under CVA, and under PCA the Euclidean distance in X-space with each feature divided by its total SD (`dist_x`, `all_distances_x`), which under a standardised PCA equals the 2D Z-distance at the search point (orthonormal rotated loadings) but also measures off-plane points (the `"integer"` candidates) correctly. An explicit `"euclidean"` under CVA is that X-space metric, not the plane distance. Within-pair selection (nearest valid contour vertex) is 2D Euclidean. **Under CVA the Mahalanobis selector ranks the pairs as the plane distance does, by construction:** biplotEZ builds `M = W^{-1/2} V`, so `V'WV = I/(n-g)`; the per-pair rotation `A` cancels (`A A' = I`), so `d2_M = (n-g) * dist_z^2` for in-plane points, for every pair (15992 on the loan harness; also for 2-group CVA). The thesis selects by Euclidean under PCA and Mahalanobis under CVA (final thesis p.86, §3.9.1) and says only qualitatively that plane distances correspond to Mahalanobis distances (final p.91); the (n-g) factor comes from the package's W/(n-g), since the thesis's W is the SSP (final p.48), which gives a factor of 1. The PhD code ran the pair search under CVA only. **Under PCA the Mahalanobis (`W_binary`) and Euclidean rules differ** (51 of 221 rows in `17_1`'s set-up); the PCA default is the thesis's Euclidean rule (it was `W_binary` Mahalanobis until 2026-11-05; rotation note §4.4). The rotation scripts `17_1`-`17_3` pin `distance = "mahalanobis"`, the selector their measurements used. Paper 1 (CVA) is unchanged. See the rotation note §2.5, §3.4, §4.4.
- **The boundary searches are deterministic: `.nearest_idx_block()` takes the exact nearest vertex** (`max.col(-d2, ties.method = "first")`). R's default `"random"` -- inherited from the PhD code -- treated every vertex within 1e-5 of the *farthest* vertex's squared distance as tied and drew one from the session RNG. That was the cause of the repeat-call and call-history drift the rotation note once recorded (fixed 2026-10-30; its Appendix A.2 now records the deterministic behaviour), not the rotation, which is bit-identical across calls. Never use a `max.col()`/`which.max()` variant with random ties on distances. See `documentation/nearest-vertex-tie-break.md`.
- `plot.bl_boundary()` and `bl_robustness()` standardise each variable by projection by default (`distance = "auto"`): under PCA by `X_sd` (total SD, `"euclidean"`, the thesis's §4.2.2 rule); under CVA by `sqrt(diag(W))` (within-class SD per feature, `"mahalanobis"`), the package's own choice (the thesis uses the total SD for both), which amplifies features that are good class separators (`documentation/boundary-distance-and-robustness.md` §3.3). Either can be passed explicitly. A Mahalanobis check is printed (and returned as `mahalanobis_check`) when Mahalanobis is used: the plotted measure squared, `sum(vec_to_boundary_sd^2)`, against the full `v' W^-1 v`; see `2 implementation_summary.txt` Section 4.6.1 for why the full Shapley decomposition is theoretically better but not used in Phase 2 (it is listed in `documentation/future-improvements-review.md`).

## 7. Adding a New Model Type

Two distinct paths depending on where the type should be supported.

**`bl_wrap_model()` only** (externally fitted model, complex training, or non-parsnip engine):
1. Add the type string to `valid_types` in `bl_wrap_model()` (`R/model_fit.R`)
2. Add a prediction branch in `.pred_function()` (`R/predict_utils.R`)
3. Test with the iris two-class binary dataset

**`bl_fit_model()` + `bl_wrap_model()`** (simple parsnip-compatible type; current four are GLM, SVM, NNET, RForest):
1. Add the type string to `valid_types` in both `bl_fit_model()` and `bl_wrap_model()` (`R/model_fit.R`)
2. Add a fitting branch in `.fit_model()` (`R/model_utils.R`)
3. Add a prediction branch in `.pred_function()` (`R/predict_utils.R`)
4. Test with the iris two-class binary dataset
5. Add the new type to the `@param model_type` text of the `bl_fit_model()` roxygen header

**GAMs are wrapped, not fitted:** `bl_fit_model()` has no GAM path. Fit with `mgcv::gam()`, then use `bl_wrap_model(model = <gam>, model_type = "GAM", var_names = ..., train_data = ...)` (predicts with `predict(type = "response")`), or `model_type = "custom"` with `predict_fn = function(m, new_data) as.numeric(mgcv::predict.gam(m, newdata = new_data, type = "response"))`. The README's Pima example shows the custom path; the `bl_wrap_model()` roxygen gives the `predict_fn` contract.

## 8. What Not to Show in Examples or Vignettes

- `outlie` parameter in `bl_build_grid()` — internal visual tuning only
- `calc_hull` parameter in `bl_build_grid()` — visual-only
- `bl_robustness()` called after `plot(bl_bnd)` — redundant; `plot(bl_bnd)` already prints the robustness summary to the console
- `boundary =` in `plot_biplotEZ()` — this parameter no longer exists; the correct pattern is `bl_pick_point(bl_results, bl_boundary = bl_bnd)` in an interactive session (shown with `eval=FALSE` in vignettes)
- `bl_filter_outliers()` as an explicit sequential step — outlier filtering is now integrated into `bl_prepare_data(hull_fraction = ...)`. Mention `bl_filter_outliers()` only in prose as a power-user tool for iterating on hull fractions after `bl_wrap_data()`. Never show it as a numbered workflow step.
